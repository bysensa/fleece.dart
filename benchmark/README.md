# Производительность Fleece

Нативный Dart-бенчмарк повторяет 32 сценария из Rust. Скрипт сравнения собирает и запускает исходный Rust-бенчмарк из локальной копии репозитория. [Код на Dart](throughput.dart) · [Исходный бенчмарк на Rust](https://github.com/bysensa/the-base/blob/1be207fdffd8f20d714ab8083b37442934cf77fb/crates/fleece/benches/throughput.rs)

Для `encode()` доступны CPU-профили AOT и сравнение с Rust на документе из 1 000 записей. Режим `--dict-strings` дополнительно измеряет запись 1 000 вложенных словарей с адресами и 7 000 коротких строк из тех же записей. Для обоих наборов Rust независимо строит входные данные и сверяет выходные байты. [Словари и короткие строки](dictionary-strings.md) · [Запись широких слотов](wide-slots.md) · [Предыдущая оптимизация кодировщика](encode.md)

Предыдущий замер показывает эффект объединения проверки с распаковкой в `checked.root.read()`. [Результаты чтения и записи](io.md)

## Как воспроизвести

Для отдельного замера Dart достаточно Dart SDK. Из корня пакета выполните

```sh
dart pub get
mkdir -p build
dart compile exe benchmark/throughput.dart -o build/fleece-throughput
./build/fleece-throughput
```

Для сравнения нужны Python 3, Cargo, rustc и исходники `bysensa/the-base`. Скрипт сам собирает обе реализации, проверяет входные данные и сохраняет все измерения в микросекундах. Путь к установленному Dart можно задать через `DART`, каталог сборки Cargo — через `CARGO_TARGET_DIR`.

```sh
python3 benchmark/compare.py --reference ../the-base/crates/fleece --runs 5 --csv build/throughput.csv
```

Для сравнения двух версий Dart сначала сохраните AOT-бинарник бенчмарка из исходной версии. Передайте его путь через `--baseline-dart` при запуске из изменённой версии.

```sh
python3 benchmark/compare.py --reference ../the-base/crates/fleece --baseline-dart /path/to/fleece-before --runs 5 --csv build/comparison.csv
```

## Предыдущий замер после оптимизации векторов и геометрии

Прогон от 21 ноября 2026 года выполнен на Apple M5 Pro, 18 ядер, 48 ГиБ, macOS 27.2 arm64. Для Dart использовались SDK 3.14.0 и нативная AOT-компиляция. Для Rust использованы коммит `1be207f`, rustc 1.99.1 и оптимизированный профиль `cargo bench --all-features`.

Скрипт прогрел три бинарника и выполнил пять серий по три запуска. В каждой серии исходный Dart, оптимизированный Dart и Rust запускались последовательно в отдельных процессах. Порядок запусков менялся. Два Dart-бинарника собраны до и после изменений из одного и того же файла `throughput.dart`. В каждом процессе операция повторялась не менее 300 мс. Число в таблице — медиана пяти средних значений времени на вызов. Подготовка данных и компиляция находятся вне таймера. [480 измерений сравнительного прогона](comparison.csv) · [Первоначальный замер Dart и Rust](results.csv)

Документ содержит 1 000 записей с вложенным адресом, точкой, датой, идентификатором и тегами. Перед измерением Rust и Dart независимо построили и побайтово сверили документ Fleece (220 846 байт), его JSON (333 509 байт), одну запись (272 байта, с общими ключами 202 байта) и дельту при замене поля `[500].age` (4 026 байт).

Чтение одного поля использует заранее разобранный путь `[500].address.city`. Для доверенного документа время включает создание `Doc.trusted`, поиск и получение строки. В сценарии с проверкой каждый вызов сначала проверяет весь документ. Полная распаковка уже проверенного документа использует `checked.root.read()`. В версии Dart из этого прогона метод отдельно проверял логическую структуру перед распаковкой. Текстовый JSON обрабатывают `dart:convert` и `serde_json` 1.0.154.

Векторные операции используют запрос размерности 768. Обе версии Dart сверены с Rust по байтам документов для всех четырёх форматов и по битам результата f32 для всех семи вычислений. Размер рядом с форматом включает вектор и название документа.

В сценариях геометрии сравниваются адаптеры для `geobase` 1.5.0 и `geo-types` 0.7.20. При чтении полигон получает собственную копию координат в `Float64List`. При первом обращении к точке по индексу создаётся список ссылок по числу точек кольца. Пары `(x, y)` заполняются по мере обращения. Сценарий с копированием в геобиблиотеку обращается к каждому X и Y.

## Результаты

На документе из 1 000 записей скорость кодирования выросла с 61,7 до 95,5 МБ/с, а проверки с полной распаковкой — с 23,0 до 41,9 МБ/с. Для Rust в том же прогоне получены 608,1 и 182,0 МБ/с. Dart читает заголовки и указатели по смещениям в исходном буфере, переиспользует короткие строки при записи и учитывает уже проверенные позиции UTF-8 при валидации ключей.

Для векторов f32 размерности 768 скалярное произведение ускорилось в 23,8 раза, косинусное сходство — в 51,3 раза. Операции `Float32x4` сохраняют порядок восьми накопителей f32 из Rust. Косинусное сходство вычисляет скалярное произведение и обе нормы за один проход. [Реализация Dart](../lib/src/values.dart) · [Реализация Rust](https://github.com/bysensa/the-base/blob/1be207fdffd8f20d714ab8083b37442934cf77fb/crates/fleece/src/vector.rs#L353-L357)

Чтение полигона из 10 000 точек ускорилось с 96,62 до 4,89 мкс. Когда потребитель обходит и копирует каждую координату, полная операция занимает 110,85 мкс против исходных 128,55 мкс.

Время указано в микросекундах на операцию. Ускорение — отношение медианы исходного Dart к медиане оптимизированного Dart. Колонка Rust показывает время исходного Rust-бенчмарка на той же машине. Он округляет время до 0,01 мкс.
