# Чтение и запись Fleece

## Документ из 1 000 записей

Размер документа — 220 846 байт. Каждая запись содержит вложенный адрес, географическую точку, дату, идентификатор и массив тегов. Время указано в микросекундах на документ. Конструирование `Doc(bytes)` вынесено из таймера для `checked.root.read()` и входит в отдельную строку таблицы.

| Операция | Dart до, мкс | Dart после, мкс | Ускорение | Rust, мкс |
|---|---:|---:|---:|---:|
| `checked.root.read()`, 1 000 записей | 6 290,7 | 1 601,5 | 3,93× | 854,9 |
| `decode(bytes)`, 1 000 записей | 5 286,8 | 1 634,0 | 3,24× | 1 209,6 |
| `encode(value)`, 1 000 записей | 2 327,8 | 1 199,6 | 1,94× | 365,5 |
| `encode(value)`, одна запись | 3,07 | 2,41 | 1,28× | 0,54 |
| `Doc(bytes)`, только проверка | 1 930,3 | 1 930,4 | 1,00× | 353,1 |
| Чтение полигона, 10 000 точек | 4,91 | 4,21 | 1,16× | 2,57 |

До изменений `ValueRef.read()` сначала обходил логическое значение для проверки, затем снова проходил по нему для распаковки. Теперь читатель проверяет ограничения при создании результата. Он резервирует число элементов массива до выделения списка, учитывает строки и двоичные данные при каждом раскрытии ссылки и проверяет глубину контейнеров. Повторные ссылки на изменяемые данные дают независимые копии. [Читатель](../lib/src/decoder.dart) · [Проверки границ и ошибок](../test/decoder_test.dart)

Строгий `decode(bytes)` проверяет также указатели, ширину слотов и порядок ключей. Наследуемые словари требуют проверки физического родителя, включая скрытые поля. Для такого поддерева используется валидатор графа, а в результат попадают видимые поля. При обнаружении ошибки строгий декодер сверяет её с валидатором для сохранения диагностики. [Валидатор](../lib/src/validation.dart)

Кодировщик записывает числа, указатели, слоты коллекций и двоичные тела расширений в один растущий буфер. Для повторяющейся структуры словаря он переиспользует порядок ключей. Словари с одним ключом, в том числе атрибуты текста, записываются без сортировки. Упакованные координаты и элементы векторов копируются непосредственно в выходной документ. [Кодировщик](../lib/src/encoder.dart) · [Типы расширений](../lib/src/values.dart)

## По типам

Каждая операция обрабатывает документ из 128 однотипных значений. Измерены базовые типы, все 27 расширений, семь разновидностей геометрии, пять форматов вектора, обычный и размеченный текст. Для словарей есть отдельные варианты с общими ключами и с внешней базой. В сценарии `dict-inherited` запись вызывает `appendDelta` и меняет по одному из шести полей каждой записи. [Данные и код бенчмарка](types.dart)

Ускорение для каждого документа рассчитано по медианам пяти серий. В сводной медиане все 53 варианта имеют одинаковый вес.

| Операция | Стало быстрее | Медиана ускорений | Минимум | Максимум |
|---|---:|---:|---:|---:|
| Запись | 53 из 53 | 1,84× | 1,24× (string-interned) | 8,03× (int64) |
| `checked.root.read()` | 53 из 53 | 3,30× | 1,24× (uint64) | 8,70× (decimal) |
| `decode(bytes)` | 53 из 53 | 3,22× | 1,13× (dict-inherited) | 8,72× (decimal) |

## Условия и воспроизведение

Apple M5 Pro, 18 ядер, 48 ГиБ, macOS 27.2 arm64. Обе версии Dart скомпилированы одним SDK 3.14.0 в нативный AOT. Исходная версия взята из рабочего дерева перед оптимизацией. Эталон Rust собран через `cargo bench --all-features` с rustc 1.99.1. [Исходный Rust-бенчмарк](https://github.com/bysensa/the-base/blob/1be207fdffd8f20d714ab8083b37442934cf77fb/crates/fleece/benches/throughput.rs)

В основном бенчмарке все три исполняемых файла прошли прогрев. Пять серий запускались последовательно с перестановкой реализаций. Одна операция повторялась не менее 300 мс за запуск. Перед замером Dart и Rust побайтово сверили основные документы, дельту, векторные документы и результаты вычислений. [480 измерений для 32 сценариев](io-comparison.csv)

Бенчмарк по типам сверяет байты обеих сборок, включая внешнюю базу, и проверяет, что материализованное значение повторно записывается в те же байты. Для всех 53 документов эталонный Rust-декодер прочитал входные данные, а Rust-кодировщик воспроизвёл их байты, включая внешнюю базу и дельту. [Побайтовая проверка в Rust](verify_types.rs)

Перед таймером каждого сценария выполняется 16 вызовов. Измерения идут пакетами по восемь вызовов не менее 1/12 секунды. Пять пар процессов выполняются последовательно с чередованием порядка. [1 590 измерений по типам](type-comparison.csv)

Для сравнения нужны текущий и исходный каталоги пакета с выполненным `dart pub get`. Укажите исходный каталог в переменной `BEFORE`. Обе сборки используют одни и те же файлы бенчмарков из текущего каталога.

```sh
mkdir -p build
dart compile exe --packages="$BEFORE/.dart_tool/package_config.json" benchmark/throughput.dart -o build/throughput-before
dart compile exe --packages="$BEFORE/.dart_tool/package_config.json" benchmark/types.dart -o build/types-before
dart compile exe benchmark/types.dart -o build/types-after
python3 -B benchmark/compare_types.py build/types-before build/types-after --reference ../the-base/crates/fleece --runs 5 --csv build/type-comparison.csv
python3 benchmark/compare.py --reference ../the-base/crates/fleece --baseline-dart build/throughput-before --runs 5 --csv build/io-comparison.csv
```
