# Профиль записи Fleece

Следующий замер охватывает оптимизацию четырёхбайтовых слотов и отдельно измеряет запись 1 000 указателей корневого массива. [Результаты записи широких слотов](wide-slots.md)

## Измерение

Бенчмарк создаёт в памяти 1 000 записей с идентификатором, именем, почтой, возрастом, дробным числом, флагом, тегами, датой и вложенным адресом с географической точкой. Каждый вызов `encode(value)` создаёт новый кодировщик и возвращает полный документ размером 220 846 байт. Для отдельной записи используется элемент с индексом 500, его размер — 272 байта. Подготовка данных вынесена из таймера. [Бенчмарк Dart](throughput.dart) · [Исходный бенчмарк Rust](https://github.com/bysensa/the-base/blob/1be207fdffd8f20d714ab8083b37442934cf77fb/crates/fleece/benches/throughput.rs)

Среда замера 21 ноября 2026 года — Apple M5 Pro, macOS 27.2 arm64, Dart 3.14.0 AOT и rustc 1.99.1. Исходная сборка содержит код рабочего дерева непосредственно перед этой оптимизацией. Каждая из трёх реализаций проходит прогрев, затем пять серий с чередованием порядка запуска. Один замер операции длится 300 мс. В таблицах приведены медианы времени на целый документ, пропускная способность рассчитана по размеру результата.

У Rust входной `Value::Object` хранит поля в `BTreeMap`, поэтому они упорядочены ещё при подготовке данных. Dart получает обычные `Map` и определяет порядок записи их полей внутри `encode()`. [Определение Object в Rust](https://github.com/bysensa/the-base/blob/1be207fdffd8f20d714ab8083b37442934cf77fb/crates/fleece/src/value.rs#L16)

| Документ | Dart до, мкс | Dart после, мкс | Rust, мкс | Ускорение Dart | Время Dart / Rust до → после |
|---|---:|---:|---:|---:|---:|
| 1 000 записей, 220 846 байт | 1 195,874 | 621,595 | 361,19 | 1,92× | 3,31× → 1,72× |
| Одна запись, 272 байта | 2,365 | 1,405 | 0,54 | 1,68× | 4,38× → 2,60× |

На большом документе пропускная способность Dart выросла со 184,7 до 355,3 МБ/с, у Rust — 611,4 МБ/с. Разброс пяти замеров Dart после оптимизации составил 612,1–632,6 мкс. [Все пять серий для 32 операций](encoder-comparison.csv)

## Что показал профиль

Системный профилировщик macOS снимал стек потока Dart AOT с интервалом 1 мс в течение восьми секунд. Для каждой сборки профилировался только цикл записи 1 000 записей. В таблице указана доля отсчётов непосредственно внутри функции. Код, встроенный AOT-компилятором, относится к содержащей его функции. Базовый профиль содержит 6 481 отсчёт внутри измеряемого цикла, итоговый — 6 337. В CSV есть также число отсчётов с каждой функцией в стеке. [Все счётчики профиля](encode-profile.csv) · [Обработка стеков](encode_profile.py)

| Участок до оптимизации | Доля | Участок после оптимизации | Доля |
|---|---:|---|---:|
| Поиск в `LinkedHashMap` | 11,3% | Запись широких слотов, `Encoder._wideSlots` | 10,4% |
| Завершение коллекции, `Encoder._end` | 8,5% | Запись коллекции, `Encoder._collectionSlot` | 9,4% |
| Подготовка строки, `Encoder._stringSlot` | 7,1% | Приём пары ключ–значение, `_MapFields._field` | 7,2% |
| Итератор ключей, `CompactIterator.moveNext` | 4,9% | Запись словаря, `Encoder._map` | 7,2% |
| Получение вершины стека, `lastOrNull` и `List.last` | 7,9% | Поиск короткой строки в `HashMap` | 6,3% |
| Рост списков, `List._grow` | 3,8% | Запись текста, `_Output.text` | 4,7% |

- Кодировщик получает ключ и текущее значение за один обход `Map.forEach`. Для словарей до 32 полей он запоминает на текущем уровне вложенности порядок сортировки и слоты пригодных к повторному использованию ключей. Смена состава или порядка ключей пересчитывает схему. На каждый новый документ создаётся свой кодировщик.
- Крупные словари с уже упорядоченными ключами проходят линейную проверку. Если требуется сортировка, общий префикс имён вычисляется один раз и пропускается при сравнениях. У наследуемого словаря первые два слота сразу отведены под родителя. Упорядоченные изменённые поля записываются вслед за ним.
- Все открытые коллекции используют один растущий буфер слотов. Соседние коллекции на одной глубине переиспользуют рабочую память. При закрытии коллекции кодировщик пишет двухбайтовые слоты непосредственно в результат. Если хотя бы один указатель требует четырёх байт, он пересчитывает смещения и записывает широкие слоты.
- Короткие строки ASCII копируются и проверяются за один цикл. Таблица повторов хранит позиции по тексту строки. Тег расширения и тело скаляра резервируются вместе, а небольшие целые, флаги и строки можно сразу поместить в слот массива или словаря. [Кодировщик](../lib/src/encoder.dart) · [Типизированные значения](../lib/src/values.dart)

## Запись по типам

В этой серии каждый вызов записывает документ из 128 значений. Измеряются базовые типы, все 27 расширений и их варианты, включая геометрию, векторы и размеченный текст. Для `dict-inherited` измеряется полный вызов `appendDelta` с внешней базой. Сборки чередуются в пяти сериях. Для каждого типа после 16 прогревочных вызовов операции выполняются группами по восемь в течение как минимум 83 мс. До замера проверяется обратное преобразование каждого документа, затем Rust проверяет и перекодирует полученные файлы. [Данные по типам](types.dart) · [Все серии в CSV](encoder-types.csv) · [Проверка Rust](verify_types.rs)

У всех 53 вариантов медианное время записи уменьшилось. Медиана ускорений по вариантам — 1,76×. Наименьший выигрыш у дельты с наследуемым словарём (1,04×), наибольший — у `datetime` (4,20×).

| Документ из 128 значений | Dart до, мкс | Dart после, мкс | Ускорение |
|---|---:|---:|---:|
| `int64` | 3,700 | 2,799 | 1,32× |
| Строки UTF-8 | 10,159 | 9,143 | 1,11× |
| Массивы | 12,818 | 8,635 | 1,48× |
| Словари | 31,452 | 15,551 | 2,02× |
| Словари с общими ключами | 40,901 | 30,324 | 1,35× |
| Дельта с наследуемыми словарями | 306,782 | 293,785 | 1,04× |
| `datetime` | 12,266 | 2,920 | 4,20× |
| Размеченный текст | 59,441 | 37,366 | 1,59× |

## Побайтовое сравнение

Rust построил данные собственной функцией `record()`. Полные выходные буферы совпали у обеих версий Dart и Rust для 1 000 записей, отдельной записи, записи с общими ключами и дельты изменения поля `[500].age`. SHA-256 большого документа — `0e30feab8779c05e7390b8dbdff319bce9c30216bcb47bad383c1b3ba36407ab`. Сверка также охватывает четыре векторных документа и биты результатов векторных операций. [Проверка на Rust](verify_inputs.rs)

В наборе по типам исходная и оптимизированная сборки Dart выдали одинаковые файлы. Rust перекодировал все 53 документа с побайтовым совпадением, включая словарь с общими ключами и дельту с внешней базой. [Проверка документов по типам](compare_types.py)

В отдельном корпусе совместимости Dart и Rust побайтово совпали на 307 из 307 документов. При сравнении с Couchbase C++ все 307 документов прошли перекрёстное чтение, у 85 совпали также байты. Проверки применения дельт прошли для 400 пар и для 200 документов с шестью последовательными дельтами. [Скрипт совместимости](../test/reference/couchbase.py)

Регрессионные тесты охватывают смену схемы словаря, ключи с равным текстом в `Map.identity`, порядок Unicode, положение родителя перед числовыми ключами, границу двухбайтового внешнего указателя и восстановление после некорректного UTF-16. [Тесты кодировщика](../test/document_test.dart)

## Воспроизведение

Для обеих версий Dart используется один и тот же код бенчмарка. `before` указывает на исходную версию пакета с выполненным `dart pub get`, `crate` — на Rust-крейт Fleece. Сравнение собирает Rust в профиле `cargo bench --all-features` и проверяет байты перед замерами.

```sh
before=/path/to/before/fleece.dart
crate=../the-base/crates/fleece
mkdir -p build/profile
dart compile exe --packages="$before/.dart_tool/package_config.json" benchmark/throughput.dart -o build/profile/throughput-before
dart compile exe --packages="$before/.dart_tool/package_config.json" benchmark/types.dart -o build/profile/types-before
dart compile exe benchmark/types.dart -o build/profile/types-after
python3 benchmark/compare.py --reference "$crate" --baseline-dart build/profile/throughput-before --runs 5 --csv build/profile/documents.csv
python3 benchmark/compare_types.py build/profile/types-before build/profile/types-after --reference "$crate" --write-only --runs 5 --csv build/profile/types.csv
```

Для CPU-профиля на macOS нужны AOT-снимки с символами и `dartaotruntime` из того же SDK. Профилирование и замеры времени запускаются отдельно.

```sh
dart compile aot-snapshot --packages="$before/.dart_tool/package_config.json" benchmark/throughput.dart -o build/profile/before.aot
dart compile aot-snapshot benchmark/throughput.dart -o build/profile/after.aot
runtime=/path/to/dart-sdk/bin/dartaotruntime
for version in before after; do
  "$runtime" "build/profile/$version.aot" --profile-encode 12 &
  pid=$!
  sleep 0.4
  sample "$pid" 8 1 -file "build/profile/$version.sample"
  wait "$pid"
done
python3 benchmark/encode_profile.py build/profile/before.sample build/profile/after.sample --csv build/profile/cpu.csv
```
