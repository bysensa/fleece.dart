# Запись словарей и поиск коротких строк

Исходная версия Dart — `6015d0b`, после оптимизации четырёхбайтовых слотов. Обе версии собраны в AOT одним Dart SDK 3.14.0 с одним исходником бенчмарка. Rust — `1be207f` из `bysensa/the-base`, rustc 1.99.1, оптимизированный профиль `cargo bench --all-features`. Замеры выполнены 21 ноября 2026 года на Apple M5 Pro, macOS 27.2 arm64. [Бенчмарк Dart](throughput.dart) · [Исходный бенчмарк Rust](https://github.com/bysensa/the-base/blob/1be207fdffd8f20d714ab8083b37442934cf77fb/crates/fleece/benches/throughput.rs)

## Время записи

Медианы пяти серий после прогрева, в микросекундах на документ. Каждая сборка работала отдельным процессом. Порядок сборок менялся между сериями. [Все замеры 35 операций](dictionary-string-comparison.csv)

| Документ | Dart до, мкс | Dart после, мкс | Rust, мкс | Снижение времени Dart | Время Dart / Rust до → после |
|---|---:|---:|---:|---:|---:|
| 1 000 записей, 220 846 байт | 523,566 | 466,907 | 363,420 | 10,8% | 1,44× → 1,28× |
| 1 000 словарей адресов, 53 982 байта | 137,979 | 110,631 | 108,680 | 19,8% | 1,27× → 1,02× |
| 7 000 коротких строк, 52 284 байта | 141,540 | 112,077 | 100,270 | 20,8% | 1,41× → 1,12× |
| Одна запись, 272 байта | 1,289 | 1,067 | 0,550 | 17,2% | 2,34× → 1,94× |

На полном документе Dart сэкономил 56,659 мкс, или 35,4% исходной разницы с Rust. Пропускная способность выросла с 421,8 до 473,0 МБ/с. Rust обработал 607,7 МБ/с. Диапазон пяти серий Dart составил 517,921–533,394 мкс до изменения и 459,371–477,282 мкс после.

Закрытие уже подготовленного корневого массива с 1 000 широких слотов заняло 1,822 → 1,804 мкс, у Rust — 1,155 мкс. В дополнительном контроле из 21 пары запусков `--wide-root` с чередованием порядка медианы составили 1,848 → 1,827 мкс. Разница мала относительно разброса отдельных серий, 1,476–2,584 мкс до и 1,470–2,666 мкс после. [Все 21 пары замеров корня](dictionary-string-wide-root.csv)

## Что измеряли

Основной вызов `encode()` получает тот же список из 1 000 записей. Первый дополнительный сценарий кодирует 1 000 вложенных словарей `address` с исходными городами, почтовыми индексами и геометрией. Второй кодирует 7 000 коротких строк в порядке появления в документе. От каждой записи он берёт город, индекс, имя таблицы из идентификатора, имя пользователя и три тега. Подготовка этих списков происходит до запуска таймера. Каждая измеренная операция создаёт энкодер и возвращает готовый документ. [Построение и проверка данных в Rust](verify_inputs.rs)

В исходном Rust-бенчмарке `Object` хранит поля в `BTreeMap` с уже упорядоченными ключами. Dart получает обычные `Map` в порядке вставки и определяет канонический порядок внутри `encode()`. [Представление Object в Rust](https://github.com/bysensa/the-base/blob/1be207fdffd8f20d714ab8083b37442934cf77fb/crates/fleece/src/value.rs#L16)

## Что показал CPU-профиль

В документе 2 000 словарей и 12 000 полей. Отдельный прогон исходной версии со счётчиками зафиксировал две сортировки, 7 012 поисков коротких строк, 4 937 попаданий и 2 075 вставок. В число вставок входят 12 имён полей. В исходном профиле сбор полей занял 8,5% собственных сэмплов, обход `Map.forEach` — ещё 5,0%. На поиск `HashMap.[]` пришлось 10,1% сэмплов с учётом вложенных вызовов, на вставку `HashMap.[]=` — 4,5%. [Профили до и после](dictionary-string-profile.csv)

Теперь обход исходной `Map` и цикл записи в каноническом порядке обращаются к одним и тем же объектам полей. При смене имени сбрасывается сохранённый слот этого ключа. Для словарей до 32 полей без таблицы общих ключей энкодер заранее выделяет место под пары и сразу записывает обычные значения в их слоты. Ключ попадает в стек до обработки значения, поэтому потоковую запись можно продолжить после ошибки в значении. [Код энкодера](../lib/src/encoder.dart)

Для коротких строк энкодер использует таблицу с открытой адресацией. Один поиск по хешу возвращает указатель на первое вхождение или свободную ячейку. На промахе строка попадает в таблицу после проверки UTF-16 и записи тела длиной до 15 байт UTF-8. Таблица хранит хеш вместе со строкой, проверяет совпадение текста и повторно использует хеш при расширении. [Поиск и запись строк](../lib/src/encoder.dart)

Энкодер резервирует слоты по длине массива. В `List<String>` и `List<Map>` тип элементов известен до входа в цикл. В смешанных массивах `FleeceNone` записывается одним встроенным словом. Расширение `FleeceSet` передаёт список элементов прямо в тот же метод записи массива. [Реализация FleeceSet](../lib/src/values.dart)

В новом профиле сбор полей занимает 8,1% собственных сэмплов. Поиск в таблице встроен компилятором в `_stringSlot`, на который приходится 11,1% собственных сэмплов. Для сравнения абсолютного времени записи строк служит отдельный сценарий с 7 000 значений. Профили сняты утилитой macOS `sample` по 8 секунд с интервалом 1 мс. В измеренном цикле учтено 6 286 сэмплов до и 5 860 после. [Обработка CPU-профилей](encode_profile.py)

## Побайтовая совместимость

Rust построил данные собственной функцией `record()`. Обе версии Dart совпали с Rust во всех байтах полного документа, словарей адресов, коротких строк, отдельной записи, записи с общими ключами и дельты. Также совпали четыре векторных документа, результаты векторных операций и JSON. SHA-256 документа из 1 000 записей — `0e30feab8779c05e7390b8dbdff319bce9c30216bcb47bad383c1b3ba36407ab`. [Код побайтового сравнения](verify_inputs.rs)

В Dart VM прошли 194 теста, в Node.js — 192. Новые тесты проверяют цепочки коллизий и расширение таблицы, повторное использование строки длиной 15 байт UTF-8, отдельные тела для строки длиной 16 байт и продолжение потоковой записи после ошибки в словаре или массиве строк. [Тесты энкодера](../test/document_test.dart)

Rust воспроизвёл все 53 документа из набора тестов записи по типам. В независимом корпусе Dart и Rust выдали одинаковые байты для 307 из 307 документов. В проверке с Couchbase успешно прошли 400 пар документов и 200 цепочек из шести последовательных дельт. Дополнительно сборки Dart для JavaScript и WebAssembly в Node.js повторно закодировали полный документ, адреса и короткие строки с побайтовым совпадением во всех трёх случаях. [Проверка типов в Rust](verify_types.rs) · [Независимый корпус](../test/reference/couchbase.py)

## Как воспроизвести

Переменная `before` указывает на рабочую копию исходной версии с выполненным `dart pub get`. Команды запускаются из изменённой версии.

```sh
before=/path/to/fleece-at-6015d0b
crate=../the-base/crates/fleece
mkdir -p build/dict
dart compile exe --packages="$before/.dart_tool/package_config.json" benchmark/throughput.dart -o build/dict/before
python3 benchmark/compare.py --reference "$crate" --baseline-dart build/dict/before --dict-strings --wide-root --runs 5 --csv build/dict/documents.csv
dart compile exe --packages="$before/.dart_tool/package_config.json" benchmark/types.dart -o build/dict/types-before
dart compile exe benchmark/types.dart -o build/dict/types-after
python3 benchmark/compare_types.py build/dict/types-before build/dict/types-after --reference "$crate" --write-only --runs 5 --csv build/dict/types.csv
```

Для профилирования обе AOT-сборки запускаются с `--profile-encode 12`. [Команды для macOS sample](encode.md#воспроизведение)
