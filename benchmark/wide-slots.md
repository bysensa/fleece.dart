# Запись четырёхбайтовых слотов

Сравнение использует тот же документ из 1 000 записей размером 220 846 байт и запись с индексом 500 размером 272 байта. Исходная AOT-сборка сохранена перед изменением записи слотов. Прогон выполнен 21 ноября 2026 года на Apple M5 Pro под macOS 27.2 arm64, с Dart 3.14.0 и rustc 1.99.1. Эталон — коммит `1be207f` из `bysensa/the-base`. [Данные и бенчмарк Dart](throughput.dart) · [Исходный бенчмарк Rust](https://github.com/bysensa/the-base/blob/1be207fdffd8f20d714ab8083b37442934cf77fb/crates/fleece/benches/throughput.rs)

| Операция | Dart до, мкс | Dart после, мкс | Rust, мкс | Ускорение Dart | Время Dart / Rust до → после |
|---|---:|---:|---:|---:|---:|
| Записать 1 000 широких указателей корневого массива | 2,610 | 1,479 | 1,136 | 1,76× | 2,30× → 1,30× |
| Полный `encode()`, 1 000 записей | 612,339 | 515,531 | 360,62 | 1,19× | 1,70× → 1,43× |
| Полный `encode()`, одна запись | 1,402 | 1,291 | 0,54 | 1,09× | 2,60× → 2,39× |

На большом документе время Dart сократилось на 15,8%, а пропускная способность выросла с 360,7 до 428,4 МБ/с. У Rust — 612,4 МБ/с. Пять серий полного `encode()` дали 511,6–529,3 мкс для обновлённого Dart. Для короткого замера корня разброс составил 1,476–2,515 мкс после оптимизации и 2,553–3,359 мкс до неё. [Исходные замеры всех 33 операций](wide-slot-comparison.csv)

В отдельном наборе из 53 документов по 128 однотипных значений медиана ускорений записи составила 1,14×. Медианное время снизилось во всех 53 случаях. Меньше всего изменилась дельта с наследуемым словарём (290,571 → 289,863 мкс), больше всего ускорилась запись массива `null` (1,410 → 1,047 мкс, 1,35×). На этих сценариях сказывается в том числе изменение общего буфера слотов. [Замеры по всем типам](wide-slot-types.csv)

## Что изменилось

В большом документе 5 001 коллекция. Четырёхбайтовые слоты используются в 3 231 коллекции. На них приходится 22 812 указателей и 1 615 встроенных значений. В каждой из этих коллекций ширина известна по первому указателю. В общем случае дальний указатель может находиться в любом месте коллекции.

- Когда первый указатель требует четырёх байт, кодировщик сразу резервирует полное место. Если дальний указатель встречается позже, кодировщик перезаписывает узкий префикс и обнуляет оба байта дополнения у встроенных значений.
- В нативной сборке основной буфер и временный буфер сортировки имеют конкретный тип `Int64List`. Дизассемблирование AOT для arm64 показало, что компилятор заменил косвенный вызов `operator[]` внутри цикла обычной загрузкой из памяти. В веб-сборке слоты хранятся в списке целых.
- Кодировщик проверяет, что расстояние в байтах положительно и чётно, а расстояние в двухбайтовых единицах помещается в 30 бит. Затем он записывает четыре байта в порядке Fleece. Внешний указатель получает флаг `0x40` в старшем байте. Заголовок коллекции записывается один раз после выбора ширины. [Реализация](../lib/src/encoder.dart)

## Как измерено

Основное время — полное `encode(value)`. Прогрев предшествует пяти сериям с чередованием порядка запуска двух Dart AOT-сборок и Rust. Каждая операция основного бенчмарка выполняется в течение 300 мс. Сравниваются медианы по сериям.

Дополнительная строка `close wide root` измеряет только `endArray()` корневого массива того же документа. До запуска таймера каждый кодировщик уже записал все вложенные поля. Закрытие массива записывает заголовок и 1 000 четырёхбайтовых указателей. Обе реализации проверяют результат через сравнение с полным `encode()`. В каждой серии после двух прогревочных групп измеряются 64 группы по восемь кодировщиков. Вызов `finish()` вынесен за таймер в обоих языках. [Измерение в Dart](throughput.dart) · [Измерение в Rust](verify_inputs.rs)

Для CPU-профиля `sample` отдельно снимал стек AOT-потока в течение восьми секунд с интервалом 1 мс. Доля отсчётов непосредственно внутри `_wideSlots` снизилась с 10,9% (689 из 6 335) до 8,1% (510 из 6 292). С учётом вызываемых функций — с 13,5% до 8,3%. [Счётчики по функциям до и после](wide-slot-profile.csv)

## Проверка байтов

Проверка строит входные значения собственной функцией `record()` из Rust и сравнивает буферы обеих версий Dart с результатом Rust. В основной набор входят 1 000 записей, одна запись, запись с общими ключами и дельта поля `[500].age`. SHA-256 документа из 1 000 записей — `0e30feab8779c05e7390b8dbdff319bce9c30216bcb47bad383c1b3ba36407ab`. [Сверка по байтам](verify_inputs.rs)

Rust также воспроизвёл все 53 документа по типам с точным совпадением байтов, включая дельту и её внешнюю базу. Для JavaScript и WebAssembly отдельно проверено чтение и обратное кодирование большого документа в Node.js 24.22.3. Оба результата совпали со всеми 220 846 байтами эталона. [Сверка документов по типам](verify_types.rs)

В корпусе совместимости Dart и Rust записали одинаковые байты для 307 из 307 документов. Проверка дельт с Couchbase прошла для 400 пар и 200 документов с шестью последовательными дельтами. Полный набор тестов пакета прошёл на Dart VM (192 теста) и в Node.js (190). [Проверка совместимости](../test/reference/couchbase.py)

Тест для внешней базы размером `0x02040608` байт проверяет все четыре байта дальнего указателя, короткий внешний указатель в широком слоте, локальный указатель, дополнение встроенного числа и тег расширения. Один вариант начинает массив с дальнего указателя, другой переключает ширину после двух значений. Оба ожидаемых 26-байтовых документа сверены с Rust. [Регрессионный тест](../test/document_test.dart)

## Как воспроизвести

Соберите обе версии с одним исходником бенчмарка. Переменная `before` указывает на рабочую копию предыдущей версии пакета с выполненным `dart pub get`.

```sh
before=/path/to/before/fleece.dart
crate=../the-base/crates/fleece
mkdir -p build/wide
dart compile exe --packages="$before/.dart_tool/package_config.json" benchmark/throughput.dart -o build/wide/before
python3 benchmark/compare.py --reference "$crate" --baseline-dart build/wide/before --wide-root --runs 5 --csv build/wide/documents.csv
dart compile exe --packages="$before/.dart_tool/package_config.json" benchmark/types.dart -o build/wide/types-before
dart compile exe benchmark/types.dart -o build/wide/types-after
python3 benchmark/compare_types.py build/wide/types-before build/wide/types-after --reference "$crate" --write-only --runs 5 --csv build/wide/types.csv
```

Для отдельного замера закрытия корня доступен режим `--wide-root` у скомпилированного Dart-бенчмарка. CPU-профиль строится в режиме `--profile-encode`. [Команды профилирования AOT](encode.md#воспроизведение)
