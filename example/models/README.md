# Dart-классы и документы Fleece

Сгенерированный класс принимает бинарный документ. `NoteRecord(bytes)` реализует интерфейс `Note`, включая геттер `address`. Обратиться к городу можно через `note.address.city`. Метод `toModel()` создаёт отдельный экземпляр исходного класса, а `toFleece()` возвращает байты. [Исходная модель](lib/note.dart) · [Сгенерированный код](lib/note.fleece.g.dart) · [Программа](bin/main.dart)

## Запуск

Из корня репозитория выполните

```sh
cd example/models
dart pub get
dart run build_runner build
dart run bin/main.dart
dart test
```

Программа выводит `Lyon: 0`, затем `Paris: 1`. После отката следующей транзакции в сохранённом документе остаются `Paris` и `1`.

При обновлении с прототипа повторите `dart run build_runner build` в приложении. Это обновит типы геттеров коллекций и добавит статический кодек к сгенерированным классам.

## Как задать имена

В `build.yaml` приложения настройте билдер `fleece_generator:fleece_model`. По умолчанию шаблон `{name}Document` даёт класс `NoteDocument`. В этом примере выбраны следующие параметры. [Полный build.yaml](build.yaml)

```yaml
targets:
  $default:
    builders:
      fleece_generator:fleece_model:
        options:
          class_name: '{name}Record'
          strip_prefix: '_'
          strip_suffix: Model
```

`strip_prefix` и `strip_suffix` удаляют указанные начало и конец исходного имени, если они есть. Затем `class_name` подставляет результат вместо `{name}`. Здесь `Note` становится `NoteRecord`, а `_MeterModel` — `MeterRecord`. Можно поставить маркер в конце (`Stored{name}`) или оставить только `{name}`, чтобы открывать приватно описанную модель как `Meter(bytes)`.

Чтобы задать имя одному классу, используйте `@FleeceModel(name: 'Shipment')`. Оно имеет приоритет над настройками билдера. Результат должен быть свободным публичным именем Dart в этой библиотеке. После изменения настроек запустите `dart run build_runner build` и обновите обращения к переименованным классам. Ключи и байты документов сохраняют прежний формат.

## Описание модели

Подключите `fleece` к приложению, а `fleece_generator` и `build_runner` — к его `dev_dependencies`. Генератор использует Dart 3.11 или новее. Для реактивности добавьте `fleece_signals` и `signals_core`. При работе с копией репозитория укажите путь к корню для `fleece` и пути к нужным пакетам в `packages/`. [Рабочий pubspec](pubspec.yaml)

Для подключения через Git задайте всем трём пакетам один URL репозитория и один полный SHA коммита в `git.ref`. Для генератора укажите `git.path: packages/fleece_generator`, для сигналов — `git.path: packages/fleece_signals`. Pub привязывает относительную зависимость `fleece_signals` от `fleece` к конкретному коммиту. Такой же SHA у прямой зависимости `fleece` позволяет использовать их вместе.

```dart
import 'package:fleece/model.dart';

part 'address.fleece.g.dart';

@FleeceModel()
class Address {
  const Address(this.city, {this.postcode});
  final String city;
  final String? postcode;
}
```

Параметры конструктора задают сохраняемые поля. По умолчанию генератор использует безымянный конструктор. Для именованного укажите `@FleeceModel(constructor: 'stored')`. У каждого параметра должен быть публичный геттер того же типа. Поддерживаются позиционные и именованные параметры, значения по умолчанию и переименование ключа через `@FleeceKey('display.title')`. Точка в этом имени является частью ключа. Для вложенных моделей из другой библиотеки импортируйте библиотеку модели целиком. Можно использовать префикс импорта.

Класс с одними хранимыми полями открывается без создания исходного объекта. Если у модели есть методы или вычисляемые свойства, сгенерированный класс наследует их реализацию. Для этого он вызывает обычный конструктор модели либо конструктор доступной реализации перенаправляющей фабрики. В таком случае аргументы конструктора читаются при открытии. Геттеры и сеттеры хранимых полей продолжают обращаться к документу.

Обычный сеттер записывает одно поле. Если у свойства есть свой сеттер, библиотека вызывает его на отдельном экземпляре исходного класса и переносит изменившиеся поля в ту же транзакцию. Так сохраняются нормализация, проверки и правки соседних полей. Исключение из сеттера отменяет это присваивание. Этот путь требует распаковки модели. В унаследованных методах и вычисляемых свойствах обращайтесь к сохраняемым значениям через публичные свойства модели. Приватная переменная экземпляра суперкласса сама по себе не отслеживает коммиты документа.

```dart
final bytes = const Address('Минск').toFleece();
final Address original = AddressRecord.codec.decode(bytes);
final address = AddressRecord(bytes);
address.city = 'Брест';
final Address detached = address.toModel();
```

Кодек последовательно пишет ключи и значения в `Encoder` в порядке UTF-8, принятом в `fleece::encode`. Чтение находит значения в бинарном словаре и передаёт их в конструктор. Для старых документов отсутствующий ключ получает значение по умолчанию или `null` для nullable-поля. Отсутствующее обязательное поле без такого значения и несовместимый тип вызывают `FormatException`.

`decode()` и `toModel()` возвращают собственные коллекции экземпляра, в том числе для отсутствующих полей с `const []` и `const {}` в конструкторе. Объявленный через `super` параметр наследует значение по умолчанию родительского конструктора.

| Поле Dart | Представление в Fleece |
| --- | --- |
| `bool`, `String`, `int`, `double`, `num` | Соответствующий скаляр. Поле `double` всегда записывается как f64 |
| `BigInt` | Стандартное целое в диапазоне от −2⁶³ до 2⁶⁴ − 1 |
| `Uint8List` | Бинарные данные |
| `DateTime` | Расширение datetime. При чтении возвращается UTC с точностью до микросекунды |
| `enum` | Строковое имя варианта |
| Аннотированный класс, `List<T>`, `Map<String, T>` | Вложенный словарь, массив, словарь. Типы элементов могут быть nullable |
| `Object`, `Object?`, `dynamic` | Любое значение основного кодека. Для `Object` значение `null` вызывает ошибку |
| `FleeceFloat32`, `FleeceFloat64`, типы `FleeceValue` | Собственный тип Fleece, включая UUID, типизированные числа и datetime с наносекундами |

## Обобщённые модели и пользовательские кодеки

Для каждого параметра типа генератор добавляет именованный аргумент кодека. У `Envelope<T>` это `codecT`. Одна модель может использовать разные представления в разных местах приложения.

```dart
@FleeceModel(constructor: 'stored')
class Envelope<T> {
  const Envelope.stored(this.value);
  final T value;
}

final codec = EnvelopeRecord.codec<int>(codecT: FleeceCodecs.integer);
final bytes = codec.encode(const Envelope.stored(42));
final Envelope<int> value = codec.decode(bytes);
final document = EnvelopeRecord<int>(bytes, codecT: FleeceCodecs.integer);
document.value++;
```

Если тип использует прикладное представление, опишите чтение одного `ValueRef` и запись одного значения в `Encoder`. Аннотация поля применяется и к элементам вложенных коллекций. Для `T` в обобщённой модели такой же кодек можно передать при открытии. [Модели и кодек Uri](test/fixtures.dart) · [Сравнение с байтами Rust](test/generic_codec_test.dart)

`document.toFleece()` сохраняет текущее представление. Чтобы сменить представление параметра типа, передайте другой кодек через `document.toFleece(codecT: other)` или `EnvelopeRecord.codec<T>(codecT: other).encode(document)`. При этом перекодируются присутствующие поля, которые зависят от изменившегося параметра. Неизвестные ключи и значения остальных полей копируются из исходного документа.

```dart
class UriCodec extends FleeceCodec<Uri> {
  const UriCodec() : super(_write, _read);
  static void _write(Encoder e, Uri value) => e.writeString(value.toString());
  static Uri _read(ValueRef ref) => Uri.parse(FleeceCodecs.string.read(ref));
}

@FleeceModel()
class Links {
  const Links(this.urls);
  @FleeceUseCodec(UriCodec)
  final List<Uri?> urls;
}
```

Если исходная модель уже определяет свойство или метод `codec`, сгенерированный кодек доступен через `$ИмяМоделиFleeceFormat.codec`. При совпадении имён операций с методами модели можно явно вызвать extension, например `NoteRecordOperations(note).transaction(...)`.

## Транзакции и подписки

- `note.address.city` читает поле из текущего буфера. Сохранённая ссылка `final address = note.address` остаётся актуальной после коммита. `address.toModel()` даёт самостоятельный снимок подмодели.
- Сеттер `note.visits++` публикует отдельную транзакцию. Для группы правок вызовите `note.transaction((draft) { ... })`. Черновик имеет тот же тип, что и `note`. Его геттеры сразу видят правки, а `note` продолжает читать прежнюю версию до коммита. Для асинхронной функции используйте `await note.transaction(...)`. Исключение в функции отменяет её правки.
- Для явного управления используйте `final draft = note.beginTransaction()`, меняйте поля самого `draft`, затем вызовите `draft.commit()` или `draft.rollback()`. Одновременно у документа может быть один активный черновик.
- В `transaction` черновиком управляет сама функция. Попытка вызвать у него `commit()`, `rollback()` или `dispose()` приводит к `StateError`. Выход по исключению, в том числе после `await`, отменяет транзакцию.
- Коммит копирует достижимые значения в новый буфер, разворачивает унаследованные словари, проверяет результат и заменяет текущую версию. Стоимость сборки зависит от размера всего актуального документа. `note.toFleece()` возвращает копию байтов. При использовании `SharedKeys` сохраняйте `note.sharedKeyState` вместе со снимком.
- Правка `draft.address.city` сохраняет соседние поля, в том числе неизвестные схеме. Присваивание `draft.address = Address(...)` заменяет всё содержимое этого поля.
- Коллекции поддерживают операции Dart напрямую. Например, `draft.tags.addAll(tags)`, `draft.destinations['N'] = [Address('Рига')]` и `draft.destinations['N']![0]!.city = 'Брест'`. Каждая пакетная операция атомарна, включая случай, когда переданный итератор или функция выбрасывает исключение. Последовательные добавления в одном черновике записываются при сборке массива.
- Вложенные списки и словари внутри `dynamic` и `Object?` тоже связаны с документом. Например, `draft.attributes['flags']['enabled'] = true` попадает в текущую транзакцию. Поле `Uint8List` при чтении даёт отдельный буфер. Изменённые байты сохраняются присваиванием полю.
- Сохранённая ссылка на вложенную модель следует за путём. После сортировки `items[0]` указывает на данные по этому индексу. `removeAt` и `Map.remove` возвращают удалённое значение, которым можно пользоваться отдельно. Для самостоятельной копии исходной модели и её коллекций вызовите `toModel()`.
- Эффект, читающий `map.containsKey('x')`, реагирует на появление и удаление этого ключа. `map.keys` отслеживает состав словаря, `list.length` — размер массива, а `list[i]` — элемент. Чтобы сохранить список значений на момент запуска эффекта, прочитайте `list.toList()`.
- При `tracking: FleeceSignals.new` обычные геттеры участвуют в `effect` и `computed` из `signals_core`. Изменённые поля публикуются одним вызовом `batch` после коммита. При откате, повторной записи того же значения или правке соседнего поля эффект остаётся в покое. Остановите свои эффекты и вызовите `note.dispose()`, когда документ больше не нужен.
